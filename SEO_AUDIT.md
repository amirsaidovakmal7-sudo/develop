# SEO-аудит akmal.dev

Дата: 2026-10-04. Аудит проведён на локальной сборке (`frontend/dist` + Django, `127.0.0.1:8765`). Разобраны пять страниц на трёх языках, три конкурента, поисковые подсказки Google и Яндекса (регион — Ташкент). Код в этом этапе не менялся.

Как собирались данные:
- что видят боты без JS — `curl` с User-Agent `TelegramBot` и `Googlebot`, плюс Chrome с отключённым JS;
- полный рендер — Puppeteer по каждой странице и языку: заголовки, абзацы, слова, alt, ссылки, JSON-LD;
- конкуренты — исходный HTML, `robots.txt`, `sitemap.xml`, леммы через pymorphy3 (во временной папке, в проект не добавлен);
- спрос — автоподсказки Google (`hl=ru/uz/en`, `gl=uz`) и Яндекса (`lr=10335`, Ташкент), и выдача поиска.

**Ограничения.** Частоты запросов недоступны (нет Wordstat / Keyword Planner), поэтому уровни ниже — **оценки** по подсказкам, конкурентам и намерению, а не цифры. Веб-поиск в этой среде работает из США, поэтому выдача — ориентир по составу конкурентов, а не точные узбекские позиции.

## 1. Сводка и приоритеты

**Главный вывод.** Сайт сейчас почти невидим для поиска по трём причинам:
- все страницы отдают поисковику одинаковые мета-теги главной и `canonical` на главную — так мы сами просим склеить внутренние страницы с главной;
- без JS страница пустая (0 слов);
- узбекская и английская версии живут на тех же адресах и не индексируются вовсе.

Тексты при этом почти не содержат слов, которыми ищут услуги: «создание сайтов», «разработка», «Ташкент», «заказать», «sayt yaratish».

| Приоритет | Проблема | Что мешает | Решение (раздел 6) |
|---|---|---|---|
| **P0** | Одинаковые title/description/og:url и `canonical → https://akmal.dev/` на всех 5 страницах | Индексации внутренних страниц, превью ссылок | Серверные мета-теги для каждой страницы и языка |
| **P0** | Без JS в `<body>` 0 слов и 0 заголовков | Боты без рендера (Telegram, Facebook, частично Яндекс) видят пустую страницу; Google индексирует с задержкой | Пререндер страниц при сборке в исходный HTML |
| **P0** | Языки переключаются через localStorage на тех же URL | uz/en не попадут в индекс, hreflang невозможен | Языковые префиксы `/uz/…`, `/en/…` |
| **P0** | Нет `og:image` и `twitter:image` | Ссылка в Telegram, WhatsApp и Facebook без картинки | PNG 1200×630 на каждый язык |
| **P1** | Нет `robots.txt` и `sitemap.xml` (оба 404) | Обход и подтверждение в Search Console и Вебмастере | Django `sitemaps` + `robots.txt` |
| **P1** | Ключевые слова почти отсутствуют, H1 внутренних страниц — одно слово («Услуги», «Проекты») | Ранжированию по коммерческим запросам | Новые тексты по карте запросов (разделы 4–5) |
| **P1** | Все 10 услуг на одной странице — одна страница на десяток разных запросов | Ранжированию по «разработка телеграм бота», «CRM» и т.д. | Отдельные страницы для 4 основных услуг (**решение за тобой**) |
| **P2** | `/about/` и `/about` — две копии | Дубли | 301 на адрес без слеша |
| **P2** | 46 изображений проектов с `alt=""` | Поиску по картинкам и смыслу страницы | Описательные alt |
| **P2** | JSON-LD один (`ProfessionalService`) и одинаковый на всех страницах | Расширенным сниппетам | Разметка по типу страницы |
| **P2** | `/contacts` — 62–87 слов | «Тонкая» страница | Короткий содержательный текст о районе работы и способах связи |

**Стратегия.** По общим запросам вроде «создание сайтов в Ташкенте» выдачу держат каталоги (top.uz, prom.uz, olx.uz, yellowpages.uz, workspace.ru) и компании с десятками страниц. Нашему сайту реалистичнее брать:
1. запросы конкретных услуг с городом («разработка телеграм бота в Ташкенте», «CRM Ташкент»);
2. длинный хвост под задачи из портфолио («бот для приёма заявок», «телеграм бот для кафе», «сайт для учебного центра»);
3. узбекский сегмент («sayt yaratish», «telegram bot yaratish»), где конкуренция заметно ниже;
4. присутствие в тех самых каталогах (раздел 7).

### 2.1. Что видят боты без JS

Все пять страниц, включая `/about/` со слешем, отдают с кодом 200 один и тот же `<head>`:

| `<title>` | «Сайты, Telegram-боты и CRM для бизнеса — Акмаль, разработчик» |
| `canonical` / `og:url` | `https://akmal.dev/` |
| `og:image`, `twitter:image` | нет |
| `<body>` | `<div id="root"></div>` — 0 слов, 0 заголовков |
| JSON-LD | один `ProfessionalService` (из шаблона) |
| hreflang | нет |

Одинаково для `TelegramBot` и `Googlebot`. Chrome с отключённым JS: `bodyText = 0`, `h1 = 0`.

Отдельно: `/nope` локально отдаёт отладочную страницу Django, потому что в `.env` включён `DJANGO_DEBUG=True`. Наш `handler404` работает только при `DEBUG=False`. **На PythonAnywhere нужно убедиться, что `DJANGO_DEBUG=False`**, иначе 404 покажет отладочную информацию.

### 3.3. Что берём

1. **Title** по схеме «Услуга + город | бренд» в пределах 60 символов (rzbtech). Город — «в Ташкенте» (есть у всех трёх).
2. **Языковые префиксы и hreflang**, как у rzbtech, но с русским на корне: адреса akmal.dev уже могли разойтись по ссылкам.
3. **Отдельная страница на услугу** (datasite, icorp). Только так «разработка телеграм бота» и «CRM» получают свой H1, title и текст.
4. **og:image 1200×630 с `og:image:alt`, полный набор OG/Twitter** (rzbtech).
5. **JSON-LD по типу страницы:** `BreadcrumbList`, `ItemList` для проектов, `Service` (rzbtech + `Service`, которого нет ни у кого).
6. **Серверный рендер текста** (у всех троих текст есть в исходном HTML — у нас нет).
7. **Объём текста на страницах услуг 400–700 слов** с перечнем «что входит», примерами из портфолио и ответом на вопрос о стоимости. Это золотая середина между rzbtech (мало) и icorp (2400 слов, тяжело читать).

### 3.4. Что не берём

- «№1», «ТОП-1», «30+ проектов», «команда 20 человек», «более 1000 проектов» — у нас запрещено выдумывать, и мы не команда.
- `meta keywords`: Google их не использует, Яндекс тоже давно не учитывает. Это лишний шум и подсказка конкурентам.
- Description длиннее ~160 символов (icorp) и длинные title, набитые брендами партнёров.
- Страницы без H1 (datasite) и дублированные блоки заголовков (rzbtech повторяет H2/H3 дважды для мобильной и десктопной версии).
- Sitemap с чужим доменом (datasite) — у нас домен будет зафиксирован.
- Цены вроде «от 25 000 000 сум» (rzbtech): цен у нас нет, выдумывать нельзя.

### 3.5. Выдача по главным запросам (ориентир)

## 4. Карта запросов

Уровни:
- **Ядро** — коммерческие запросы основных услуг, есть в подсказках Google и Яндекса, есть у конкурентов в title.
- **Средний** — коммерческие уточнения, подсказки есть.
- **Хвост** — конкретные задачи, спрос узкий, но целевой.
- **Инфо** — информационные, отвечаем коротким абзацем на странице услуги, без блога.

«✓G / ✓Я» — запрос найден в подсказках Google / Яндекса (Ташкент). Целевые страницы указаны для **рекомендуемой структуры** с отдельными страницами 4 услуг (раздел 6.2). Если её не делаем, запросы услуг уходят на `/services` (с якорем пункта), а общий — на главную.

## 6. Технический план

### 6.1. Языковые адреса — **нужно твоё решение**

Рекомендую:
- русский на корне: `/`, `/about`, `/services`…;
- узбекский и английский под префиксами: `/uz/…`, `/en/…`;
- адрес — единственный источник правды о языке; localStorage больше не решает, что показать;
- переключатель — обычные ссылки на ту же страницу другого языка;
- **без автоматических редиректов** по языку браузера: поисковые боты приходят без языка и должны получать ту версию, что по адресу;
- hreflang `ru`, `uz`, `en` и `x-default → ru` в `<head>` и в sitemap;
- `<html lang>` по адресу.

Почему не как у rzbtech (`/ru` тоже с префиксом): ссылки akmal.dev без префикса уже могли разойтись, а русский — основной язык. Корень без префикса сохраняет их без редиректов.

### 6.2. Отдельные страницы для 4 основных услуг — **нужно твоё решение**

Без них у каждой услуги нет своего title, H1 и текста, и по «разработка телеграм бота» или «CRM» сайт конкурирует одной общей страницей. Предлагаю:
- адреса `/services/websites`, `/services/telegram-bots`, `/services/telegram-mini-app`, `/services/crm` (× 3 языка = 12 новых URL);
- собрать их из существующих компонентов (герой страницы с объектом из частиц, список «что входит», карточки проектов, форма), без нового визуального языка;
- `/services` остаётся хабом всех 10 услуг.

Это самый сильный пункт для роста в поиске, но это 4 новые страницы и новые тексты. Можно сделать сейчас или вторым этапом после запуска SEO-основы.

### 6.3. Ключевая фраза в H1 внутренних страниц — **нужно твоё решение**

Сейчас H1 — одно огромное слово («УСЛУГИ»). Длинная фраза тем же стилем 120 px сломает героя. Варианты:
- **(А, рекомендую)** H1 из двух строк: большое слово как сейчас + вторая строка тем же стилем, что вводный абзац (существующий токен `--fs-lead`), например «разработка сайтов, Telegram-ботов и CRM в Ташкенте». Визуально это небольшое добавление под большим словом.
- **(Б)** H1 оставить одним словом, ключ нести через title, description и первый абзац. Слабее.

### 6.4. Серверные мета-теги и текст в исходном HTML

1. **Один источник текстов.** Node-скрипт при `npm run build` читает словари `i18n` (как уже делает `check-i18n.ts`) и пишет `dist/seo/meta.json` — title, description, OG-alt для каждого маршрута и языка. Django читает этот JSON. Ручных копий в Python нет.
2. **Шаблон** получает от Django по маршруту и языку:
   - `title`, `description`, `canonical` (абсолютный, без слеша);
   - `hreflang` (все языки + `x-default`);
   - `og:type/site_name/title/description/url/image/image:width/height/alt`, `og:locale` + `og:locale:alternate`;
   - `twitter:card=summary_large_image` + `title/description/image`;
   - `robots`, `lang`, JSON-LD страницы;
   - мета проверки владения из `GOOGLE_SITE_VERIFICATION` и `YANDEX_VERIFICATION`, только если переменные заданы.
3. **Пререндер** при сборке. Puppeteer (уже в devDependencies) открывает каждый маршрут × язык из `vite preview` или Django и сохраняет готовую разметку `#root` в `dist/prerender/<lang>/<page>.html`. Django вставляет её в `<div id="root">`. React (`createRoot`) при загрузке заменяет её той же самой разметкой. Посетитель видит то же самое, бот без JS — полный текст, заголовки и ссылки. Это не клоакинг: содержимое идентично.
   - Риски: моргание при замене разметки, состояние закреплённой сцены в снимке. Проверю на этапе 5. Если моргание заметно — переключу на `hydrateRoot` или сниму снимок до запуска анимаций.
   - Chrome нужен только на машине сборки. `dist` и так собирается локально и хранится в git.
4. **`DocumentMeta.tsx`** после клиентской навигации ставит те же значения из тех же словарей; добавлю hreflang и `og:image`.

### 6.7. Адреса и редиректы

- `/about/` → **301** на `/about`. Для всех страниц и языков. Выбираю 301, а не только `canonical`: адрес один, ссылочный вес не делится.
- `http` → `https` и `www` → без `www`. Делается на хостинге: в PythonAnywhere включить «Force HTTPS», `www` — отдельным redirect-приложением или DNS. В Django — `SECURE_PROXY_SSL_HEADER` и флаги безопасности из переменных окружения, чтобы не сломать локальную разработку.
- Неизвестные адреса — 404 с нашей страницей (при `DEBUG=False`).

### 6.8. `sitemap.xml` и `robots.txt` (этап 4)

**`sitemap.xml`:**
- `django.contrib.sitemaps` в `INSTALLED_APPS`; `requirements.txt` не меняется;
- все страницы × 3 языка, у каждой `xhtml:link hreflang` на все версии и `x-default`;
- домен берётся из настройки `SITE_ORIGIN` (переменная окружения, по умолчанию `https://akmal.dev`), а не из заголовка Host — на PythonAnywhere он может быть `develop.pythonanywhere.com`;
- `lastmod` не указываю, пока нет реальной даты.

**`robots.txt`** — текстовый ответ Django:
```
User-agent: *
Allow: /
Disallow: /admin/
Disallow: /order
Sitemap: https://akmal.dev/sitemap.xml
```
`/static/` не закрываю.

Маршруты подключаются в `project/urls.py` до `include('app.urls')`.

### 6.9. Мелочи разметки

- alt для всех скриншотов проектов (из названия и подзаголовка проекта, на языке страницы);
- контекстные внутренние ссылки: панель услуги → страница услуги, проект → его услуга, услуга → примеры;
- номера услуг через CSS-счётчик, а не в тексте H2;
- «Что входит» — не заголовок.
